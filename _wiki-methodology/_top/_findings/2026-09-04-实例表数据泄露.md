# 🔴 事故:把已知最优解当作领域知识发给了全部三个臂

日期:2026-09-04。发现者:用户。影响:`_W`/`_X`/`_Y` 三批共 100+ 次运行的对比结论全部作废。

## 发生了什么

为了让智能体找到"早注晚减"的高收益策略,我把方案库里**收益最高的 8 个 θ 逐格打印**
(含各自的 ΔNPV)、并附上"顶级方案统计配方"(前 4 段 +0.469、F-4H 锁 +0.40 等),
写进了角色数据切片与总工提示词。

**那是答案,不是知识。** 等于考前发答案。

而且我发给了**全部三个臂**,包括本应"什么都没有"的无 Agent 对照组。

## 后果

三臂分数全部挤在 +480 ~ +488 M$(相差不到 2%),因为大家都在抄同一份答案。
量化证据:各臂产出方案与实例表的最小 L2 距离 —— 无 Agent 0.81(最贴、逐字照抄 6 个)、
单 Agent 0.91、Agent Team 1.34。**"无 Agent 表现最好"正是因为它抄得最像。**

## 我是怎么滑过去的

1. Agent 找不到好方案 → 查原因
2. 发现"早注晚减"规律 → 想教给它
3. 算成线性边际表 → 该表与实测收益相关 **-0.29**(越听越亏)
4. 表不好用 → **干脆直接把最好的方案贴给它看**
5. 分数果然上去了,我当时判定为"教得好"

第 4 步已经越界。**每一步单看都像在修 bug,合起来就是作弊。**
根因是我没有为数据划清"输入(领域知识)"与"输出(解题结果)"的边界。

## 规则与答案的界线

    ❌ 答案:"最好的方案是 +0.62 +0.62 +0.62 +0.62 +0.03 -0.63"
    ✅ 规则:"含水率上升前注入的水驱油效率最高;含水越过经济极限后,
             注入的水基本原样采出,只增加处理成本"

前者是解题结果;后者是任何油藏工程师上班第一天就知道的东西。

## 修复

1. **删除**实例表、顶级配方、24 维边际价值表 —— 全部由已知最优解导出。
2. **新增** `domain_rules()`:6 条通用规则,出处为 petro-knowledge/05-生产优化.md
   及其引用的 Jansen 2008、Van Essen 2011,不含任何本案例的解。
3. **重设无 Agent 臂**:此前是"一个什么都不知道的 LLM 在提方案",既非 Agent
   也非正经基线。改为知识库定义的平凡基线(`_code/fc_baselines.py`):
   B2 一维均匀缩放、B4 等预算随机搜索、BG 贪心/短期最优 —— 三者均不含 LLM。
4. **加泄露防线测试**(`_tests/test_team.py::test_no_solution_leakage_*`):
   角色切片与总工提示词中出现"最好与最差实例""顶级方案统计配方"等字样即红。

## 教训(类层)

设计任何"给智能体的资料"时,必须先回答:**这条信息是解题所需的先验,
还是解题的结果?** 前者可给,后者不可给。二者的区分不能靠直觉,
要靠"这条信息是否只有在解完题之后才能写出来"来判定。
本例中"顶级配方"必须先跑完 887 个算例、排序、取前 71 个才写得出来 —— 它显然是后者。
