# 估计问题 vs 决策问题：基线不能混用

**判据**：动手设计对照之前，先问"我这个问题的输出是**一个数**还是**一个动作**"。

| | 估计问题 | 决策问题 |
|---|---|---|
| 输出 | 一个量（连通性、效应值、参数） | 一套方案（怎么配注水、怎么调油嘴） |
| 基线 | 别的估计方法 | 别的**决策**方法 |
| 裁判 | 需要真值，而真值往往有争议 | **执行方案看结果**，无争议 |
| 失败模式 | 陷入"谁估得准"的循环论证 | 相对少 |

## 踩过的坑（2026-08-19 由用户点破）

本项目方向二（注水对产油的因果）本质是**决策问题**，但我按估计问题做了四天：
实现流线诊断 → 估连通性 → 和流线比谁准 → 做真值实验裁定 → 仍不一致 → 继续查。

**症结**：估计问题的"谁更准"没有天然裁判，于是在口径上反复打转
（散度当井项 → 列口径 → 发散 → 不守恒 → 归一化方向，五轮）。
而同一个问题按决策问题设计，裁判是现成的：**把方案写进 deck 重跑模拟器，比最终采收率**。

## 另一个具体坑：基线跨方向搬运

预测类基线（last-value / 历史均值 / seasonal-naive / Arps 递减）回答"未来会怎样"；
干预类基线（CRM / 流线分配 / 观测回归）回答"改了会怎样"。
**两者不可互换。** 我曾把前者列进因果实验的对照，是概念错误。

## 推论

- 能改写成决策问题的，优先改写——它自带评价协议。
- 决策问题必须有**资源约束**，否则最优解平凡（"全都拉满"）。
- 决策问题的最强立论往往不是"我比最好的方法准"，而是
  "**我比某个广泛使用但有已知缺陷的做法好**"（如贪心短视）。
