# Audit-First 协议（本项目的 SSDO 形态）

本项目不是在线服务，没有 live log / trace 流。它的"可观测性"是**实验证据的单一真源**。

## 真源

| 想知道什么 | 唯一可信来源 | 不可信来源 |
|---|---|---|
| 某个模型的指标 | `_pipelines/<实验>/results.json` | 对话里的数字、findings 文档的转述 |
| 测试是否通过 | 实跑 `gate:harness` 的 exit code | "测试写了"、"应该能过" |
| harness 是否仍与军伟可比 | 实跑 `gate:e0-replication` | 上次跑过的记忆 |
| 我们有什么数据 | `_refs/OUR_DATA_INVENTORY.md`（脚本自动生成） | 印象、任务计划里的旧描述 |

## 四条红线

1. **报任何指标前**，先读对应的 `results.json`，不引用对话记忆。
2. **改动 `_code/` 之后**，先跑 `gate:harness`，红了不许报完成。
3. **改动窗口构造、切分或指标实现之后**，必须跑 `gate:e0-replication`——它是唯一能发现"harness 悄悄变了"的端到端锚点。
4. **任何"某信息让预测变准"的主张**，先在总表里找 `verdict` 列。`FAIL(输给恒等式)` 就是没有证据，不管 MAE 多低。

## 为什么需要这条协议

2026-08-06 本项目报出过一个 42% 的提升，写进了 findings、task_plan 和 README，随后才发现是记账恒等式。
教训不是"要更仔细"，是**结论必须能被一条命令重跑验证**，且平凡基线必须在同一张表里。
